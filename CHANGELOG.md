# Changelog

All notable changes to the agent and subagent definitions, capability data, and model/effort routing are documented here.

## Unreleased

- Fix `pr-review-map` highlighting of block comments over several lines. The diff viewer highlighted each line on its own, so only a comment's opening `/**` line read as comment and the lines after it as code (keywords, strings, and types in prose). Each side of a hunk now carries an open `/* */` or HTML comment from line to line (context and removed lines on the old side, context and added lines on the new), so the lines inside read as comment through the closer and code after the closer stays code. A hunk whose first line on a side starts with `*` starts inside a doc comment when a closer follows before any opener. A language's block comments are the ones highlight.js reads as one comment over several lines. Template literals and triple-quoted strings stay per line: their opener and closer look alike, so a hunk that starts inside one would read the code after it as a string. The `sfc` browser suite checks it in both diff modes.

- Add a Visuals section to the orchestration policy: leave out secondary labels and descriptions the reader does not need, and let the layout explain the content.

- Give the `pr-review-map` page a theme switch: View › Theme (Auto, Light, Dark), also in the workspace. The pick is kept in localStorage (`review-map:theme`, one for every report) and applied by a script in the head before the first paint; Auto leaves the theme to the host page's `data-theme` (an Artifact host sets it) and else to the system, and a pick overrides both, also when the host changes the attribute later. Every colour now comes from a token with a dark value: the layer colours (hard-coded before, too dark to read on the dark map) became `--l-*` tokens, shadows `--shadow`, and the map, arrowheads, and lane dots take theirs from CSS, so a switch redraws nothing and keeps the overview's zoom. Mermaid diagrams are redrawn in mermaid's dark or default theme when the page turns dark or light: by the viewer for `--target local` (review-config carries `target`), and on an Artifact only through a `window.mermaid` the host exposes, putting the host's drawing back if that fails. A `theme` browser suite and two static checks (no colour outside the token blocks, the two dark blocks identical, the theme script before the CSS) cover it.

- Keep model choice with the user in the orchestration policy. The primary agent starts subagents only through the harness's native subagent tool, so each user-defined agent runs with the model and effort in its definition, and it does not override them. It does not delegate through a host app's own orchestration tools (for example T3 Code's `delegate_task`, `t3_thread_launch`, `create_threads`) unless the user explicitly asks for something only they provide: a separate T3 thread, a child task in its own worktree, or another provider or model.

- Give the `pr-review-map` workspace a `Lista | Mapa` switch (key `m`). In Mapa the map sits beside the diff and follows the selection (centres the file, opens its area in the overview, fades far files); above the diff a header shows the file's path, role, note (clamped with "more"), and its dependencies and dependents as chips that select the file on click and mark it on the map on hover. A diff column narrower than 900px shows unified until it widens. The step list draws arcs to the 12 nearest links and counts the rest as "+N", and conflict marks hide by default (toggle in "View") when more than a quarter of a PR's files were resolved by hand; unified diffs no longer leave the code half the width.

- Fix `pr-review-map` review findings. The viewer single-quotes a glob path in the copied `git show --remerge-diff` command and leaves the pathspec out for a group named by a list of files; the plan table keeps the order of the "Group by area" sections in both reading orders, leaves unchanged reference files out of its files, lines, and minutes (an area made only of them has no row; no changed lines take no time); the workspace remembers the address it was entered from on every way in, keeps Esc for form fields (they only lose the focus), and puts the focus on the selected step when a narrow window closes it. `build_graph.py` skips the merge-conflict check in a partial (blobless) clone with one warning, like a shallow one.
- Give `pr-review-map` a review plan. `build_graph.py` puts a `bucket` on every node (`generated` for lockfiles, Jest/Vitest snapshots, minified files, and files the overlay marks `generated: true`; else `test`, `i18n`, `docs`, or `config` from its layer; else `logic`) and a `conflict` list on a node a merge commit of the PR finished by hand: the short SHAs of the merges (the newest 50) whose recorded result for its files differs from git's automatic re-merge (`git show --remerge-diff`, git 2.36+), found also under the path a file had before the PR moved it, with a summary hint naming the files; an older git, a shallow clone, or a failing call skips the check with one warning and never stops the build. Overlay areas take an optional `depth` (`read`, `skim`, `tool`) and a short `why` (for `tool`, the check that covers the area), passed on into each PR's `clusters`; `build_graph.py` and `validate.py` refuse other values, and `validate.py` also checks `bucket` and `conflict` and warns about a `tool` area without a `why`. The viewer adds a "Plan review" table with a row per area (files, lines, depth, estimated time, conflicts), a bar of changed lines by kind, conflict badges on files resolved by hand, a collapsible graph legend, a compact "View" menu, links from `path:line` and `path:start-end` references in risks that open the diff at those lines with an "add as note" action, and a full-window workspace mode with resizable columns. `references/narrative.md` and `references/graph-prompt.md` say when to give an area its depth, to write code references relative to the repository root, to look at files resolved in merges, to leave "what to read" prose to the plan, and to state an intended behaviour change in its PR's section rather than as a risk.
- Harden `pr-review-map` after review of the import, ordering, and moved-file changes. `gen_diffs.py` embeds a file moved without changes only up to 400 lines and 4000 such lines per page (in diff order); past that the entry keeps `moved` without lines, the viewer says its lines are not in the page, and `validate.py` warns that a tour step into it opens the file. Paths git C-quotes in diff headers (a double quote, a backslash, or a control character in the name) are unquoted, which also fixes such changed files being "mapped to no node", and a moved file git cannot show no longer stops the run. `build_graph.py` reads files through one `git cat-file --batch` process per repository instead of a `git show` per file, skips a tsconfig or barrel over 1 MB with a warning, reads tsconfig files with a BOM and with commas or comment markers inside strings, and warns about one that is not JSON. `import.meta` and dynamic `import(` lines are no longer taken for import lines, and a PHP `use` inside a class (a trait) no longer makes a change look import-only. A file in a test directory named like its subject (`__tests__/utils.ts`, Django's `tests/models.py`) matches it again; only test support without a test marker gets no subject. `readFromWhy` now carries a `reason`, and the viewer says a PR has too few entry points to recommend another order instead of "only 0 of 0".
- Let `pr-review-map` find more of a large pull request's structure on its own and read it by substance. `build_graph.py` resolves `@/` and other `compilerOptions.paths` through the tsconfig.json or jsconfig.json nearest to each importer (comments and trailing commas allowed, `baseUrl` and in-repo `extends` followed), takes scoped aliases (`--alias SPEC=PATH@DIR` applies only to importers under DIR; plain `--alias` works as before and comes after tsconfig), and reports an alias whose path is in no tree. An import of an unchanged barrel is followed through its re-exports (`export *`, `export { X as Y }`, `export * as ns`, `export type`; at most 4 files deep, cycle-safe; with named imports only the re-exports of those names) to the changed files behind it, and the edge carries `via`, the barrels it went through. `import type`, `import { type A }` with every specifier a type, and `export type … from` become `type` edges, drawn dotted and lighter in the lane, the map, and the overview, with a legend entry and a mark in the neighbourhood. A test whose name matches no file falls back to its name without leading area words (`mobile-transport-test` → `transport.ts`), then to word overlap with one changed file under its package (`mobile-auth-bootstrap-test` → `auth/bootstrap.ts`), only when one file wins. First-guess layers match path segments and suffixes instead of words: component files are `ui` before a directory word claims them (`resources/js/client/**.tsx` was `infra`), fixtures, mocks, stubs, and test-utils directories are test support (`ui/fixtures` was `data`), and suffixes such as `-client.ts`, `.repository.ts`, `.controller.ts`, and `-contracts.ts` name infra, rest, and contract files. A file changed in at most 2 lines, or only in its import lines, is `trivial`; a trivial shared dependency reads after the substantive ones. The hub threshold is now max(4, ⌈1.25·√linked⌉) instead of a quarter of the linked files (13 instead of 27 at 105). Type-only edges no longer close cycles in the reading order, each real import cycle (a strongly connected component) warns once naming only its files, and breaking it never lets an unrelated file jump ahead; the viewer's `computeOrder()` applies the same rules. Each PR gets `readFrom`: "dependencies" when most of its (at least 3) entry points are trivial or change at most a third of the largest change underneath them, else "entry"; the viewer opens each PR in that mode, marks the recommended button, says why in a note, and keeps a reader's other pick per PR (`omodes`), dropped when the recommended one is picked again. `gen_diffs.py` gives a file moved without changes its whole content as context lines and `moved`, so the viewer shows it and notes and tour steps can anchor in it; its fingerprint stays the rename's. On the 151-file monorepo PR that prompted this, the scaffold now finds all 56 import edges a reviewer had added by hand (6 through a barrel, 50 through tsconfig `@/`) and 6 more tests by nearby names, reads the error and transport changes first, recommends reading from dependencies (25 of 31 entry points light), and prints no cycle warning instead of 7 for a type-only cycle.
- Keep `pr-review-map` builds and refreshes going when a tour step loses its file. A step whose file the PR no longer changes is left out with a warning (and a tour left with fewer than 3 steps with it), and a step whose file is missing on its side (a new commit deleted it) or whose lines run past the file's end goes stale with a warning and opens the whole file, keeping the previous build's lines and code; before, each of these stopped `build_graph.py` and with it `refresh.py`. `refresh.py` now writes an updated `chunks.json.new` only inside the step that cleans up after a failure, so a refresh that stops after mapping the parts leaves no side file behind.

- Add tours ("Trasy") to `pr-review-map`: named walks through one flow of a change, across PRs and the parts of a split PR. - Split a `pr-review-map` pull request too large for one map into parts cut from its commits. The new `scripts/chunks.py propose` reads the PR's first-parent history, groups consecutive commits by their conventional-commit scope (else the type, a `[prefix]`, or a task id), merges a group under 15 files into a neighbour and splits one above 60, prints a table, and writes a draft `chunks.json` for the owner to confirm; it warns when a scope comes back after others (interleaved history) and gives a merge of the base branch a part of its own, and `chunks.py expand` checks the chain and prints each part's range. `build_graph.py` and `gen_diffs.py` take `--chunks`: each part becomes a PR with its own key (the PR's key plus a letter), range, reading order, and `chunk` metadata, `parents` lists the whole PR, imports into an earlier part are cross-part edges, overlay references with the PR's key reach every part, and a file that several parts change is one node per part with its own diff and fingerprint, the last one also carrying its diff over the whole PR. `build_graph.py` suggests parts above 100 files or 60 nodes, and `assemble.py` and `validate.py` refuse a broken chain. The viewer groups the part tabs under the PR (`#251 ▸ 1/5 client-core · 34`, commits and first subjects in the tooltip), starts the groups of earlier parts' files collapsed, gives a file other parts change an "also in parts" chip and links (Polish: "Także w częściach") and a read-only "Whole-PR diff" toggle (Polish: "Diff całego PR-a"), and names the part and its commits in copied notes, whose line numbers are at that part's commits. Notes written on the whole PR's map move once to the part that holds their code (PR notes stay on the PR), and its read marks are listed as "read on the whole PR" instead of being carried over. `refresh.py` keeps the parts: new commits become a new part ("new since last version"), a rebase is remapped by patch-id or subject, a history it cannot map stops it before anything is rebuilt, and it names narrative lines that still show a part's old end. Pages without parts behave as before.
